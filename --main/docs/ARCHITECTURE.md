# Архитектура 0.5

Один Node.js/Fastify процесс отдает React SPA, PWA-ресурсы и API одного origin. PostgreSQL хранит рабочие записи. Файлы находятся в отдельном приватном volume, вне `dist`. SMTP — настраиваемый транспорт; локально Mailpit. Внешняя языковая модель подключается через отдельный отключенный по умолчанию адаптер. Микросервисов нет.

## Слои

- `src/` — прежний интерфейс; `src/live/` — авторизация, HTTP-транспорт, настройки, защищенные вложения и рабочий помощник.
- `src/store/actions.ts`, `src/reports/`, `src/wizard/` — общие бизнес-функции. Сохранены точная арифметика сметы, шаблоны, снимки и Office-экспорт. Сервер вызывает те же функции; клиентские расчеты не являются основанием разрешить запись.
- `server/app.ts` — HTTP, сессия, CSRF, rate limits, авторизация маршрутов.
- `server/contracts.ts` — ограниченные Zod-схемы; строки/массивы имеют лимиты. Незавершенный мастер допускает ошибочные исходные строки как черновик, но расчетная выгрузка блокируется валидацией.
- `server/business.ts` — применение ограниченных изменений с повторной проверкой роли и предметных правил. Переданный клиентом автор, время, шаблон, вычисленные блоки и результаты не считаются доверенными.
- `server/repository.ts` — SQL с параметрами, выборка по дому и правам, версии/аудит. Блокировка строки дома и проверка revision исключают перезапись параллельного пакета. Дополнительно сравниваются версии записей, документов, карточки и мастера.
- `server/files.ts` — размер, формат/магические байты, ограниченная потоковая проверка ZIP, запрет макросов/встроенных объектов, извлечение текста без OCR, приватное хранение.
- `server/ai.ts` — ограниченный разрешенный контекст, минимизация контактов, расходные лимиты, тайм-аут, адаптер провайдера, проверка source IDs. Никаких tools/action calls модели.

## Данные

Таблицы: accounts, sessions, password_resets, organizations, houses, premises, memberships, invitations, records, messages, record_versions, files, audit, ai_usage, auth_attempts, schema_migrations.

`records` содержит типизированные JSONB-предметные записи с отдельными house_id/collection/id/version: обращения, документы, работы, объявления, проекты мастера. Это не сохранение всей пользовательской базы одним JSON. Схемы и бизнес-валидация централизованы на API; каждая измененная запись получает неизменную строку в `record_versions`. Сообщения вынесены отдельно и получают серверного автора/время. Помещения имеют отдельную таблицу и полезную площадь; карточка и документы сохраняют свои исходные снимки. Удаление помещения из текущей карточки не переписывает старые документы или историческое членство.

Доступ к PostgreSQL и volume не опубликован. Проверки доступа реализованы в API; отдельная PostgreSQL RLS-политика не заявляется. Рабочая роль базы должна использоваться только сервером/оператором.

## Чтение и запись

`GET /api/state?houseId=...` возвращает только разрешенный набор: жителю — собственные обращения, опубликованные документы с аудиторией жителей, работы/объявления дома; полные проекты мастера, аудит и приватная карточка не возвращаются. Члены других домов не попадают в эту выборку. Список собственных доступных домов сохраняется для переключения.

Для переноса существующего интерфейса используется `POST /api/houses/:id/changes`: ограниченные изменения конкретных записей, expected revision и явный флаг подтверждения публикации. Произвольный снимок State не принимается. Сервер заново загружает данные, блокирует дом, проверяет членство/роль/версии, применяет разрешенные поля, пересчитывает/формирует документ и возвращает каноническое состояние. Клиент получает успех только после COMMIT. При конфликте — HTTP 409, ввод остается в редакторе. Уникальные редакции и версии мастера сохранены; pending-save защита не дает ответу медленного сервера затереть более поздний ввод.

Чтение истории, выгрузка дома и мастера разрешены председателю. Файлы и текстовые скачивания проверяются на сервере независимо от знания UUID. Архивирование лишает жителя чтения файла и исключает документ из AI-поиска. История и оригинал при этом не удаляются.

## Авторизация и PWA

Случайный 256-битный session token хранится у клиента только в HttpOnly cookie, у сервера — SHA-256 хеш. На HTTPS cookie Secure, SameSite=Lax, путь /api. Пароли — scrypt N=131072, r=8, p=1 и случайная соль. Сессия действует 14 дней, logout удаляет ее серверную запись, смена пароля отзывает другие сессии, восстановление — все сессии и все неиспользованные reset tokens пользователя. Reset tokens действуют 20 минут, приглашения — 3 дня; хранятся хешами и используются под блокировкой один раз.

Запись требует точного Origin, специального заголовка и CSRF-token сессии. CORS не открыт. Есть лимиты по IP, отдельные лимиты авторизации/ИИ и счетчик попыток на email с временным ограничением. Житель не может обновить роли/статус проверки дома через changes.

Рабочие данные и переписка находятся только в памяти вкладки и PostgreSQL. Service worker исключает `/api/` целиком; private responses имеют no-store. При переходе со старого worker, который мог кэшировать все GET, рабочий экран сначала проверяет privacy-version и удаляет устаревший worker/cache с перезагрузкой, не трогая демоданные. Выход/истечение сессии размонтирует рабочее состояние. Офлайн нет обещаний отправки или записи; требуется повторить после восстановления сети.
