# ҮйКөмек · 0.5.0

Рабочий MVP для ограниченного пилота ОСИ: учетные записи, отдельные дома, обращения, документы и мастер сметы с PostgreSQL и закрытым файловым хранилищем. Предыдущий демонстрационный режим сохранен отдельно. Исходный код версии 0.5 опубликован в GitHub. Рабочий сайт с сервером и базой данных отдельно не развернут.

## Запуск на Windows

1. Установите и запустите Docker Desktop (Linux containers / WSL2) и Node.js 24 LTS.
2. Распакуйте проект и откройте терминал в папке с `package.json`.
3. Выполните `npm run pilot`. Если PowerShell блокирует команду, используйте `npm.cmd run pilot`.
4. Дождитесь готовности контейнеров и откройте **http://localhost:3000/?mode=work**. Зарегистрируйтесь, создайте дом, пригласите жителя. Адрес работает на том компьютере, где запущен Docker.

Для демонстрации без учетной записи откройте `/`. Данные демонстрации не переносятся в рабочую базу автоматически. При первом запуске создается приватный `.env`; повторный запуск сохраняет базу и файлы. Не удаляйте Docker volumes для обычной остановки.

Инструкции: [запуск и ограничения пилота](docs/PILOT.md), [резервные копии](docs/BACKUP.md), [архитектура и API](docs/ARCHITECTURE.md), [результаты проверок](VERIFICATION.md).

ИИ по умолчанию выключен. Поиск по материалам дома работает отдельно и не выдается за ИИ. Настоящая почта, HTTPS, размещение и внешняя модель требуют отдельной настройки. Локальная почта для проверки восстановления пароля: http://localhost:8025. Публичного рабочего сайта пока нет; GitHub Pages не запускает этот сервер.

Ниже сохранено описание мастера и демонстрационного режима предыдущего этапа. Для рабочего режима данные сохраняются сервером; дождитесь подтверждения записи. Сметы и протоколы остаются проектами, а полномочия председателя требуют отдельной проверки.

В комплект протокола входят лист регистрации и **отдельный лист голосования на каждый вопрос** по приложению 3 к Правилам. В колонках подписей остаются пустые поля; подписи и результаты отдельных участников не создаются. Сведения о полномочиях представителей и служебные пояснения помещаются на отдельном сопроводительном листе, не меняя обязательные графы формы.

Месячный и годовой отчеты, уведомление, самостоятельная повестка, расчет взносов и письменный опрос находятся в свернутом блоке «Планируются» с основанием и пояснениями, но не выдаются за готовые мастера. Формы месячного и годового отчетов подтверждены (приложение 3 к приказу №163, формы 1 и 2), однако их заполнение пока не реализовано: требуются сведения о счетах, поступлениях и задолженности. Прежний демонстрационный обзор расходов **не заменяет установленную форму отчета**.

### Инструкция председателю

1. Войдите как председатель и выберите нужный дом. Откройте **«Мастер документов ОСИ»**.
2. В каталоге прочитайте назначение, статус, источник и «Основание и ограничения». Нажмите **«Создать документ»** у доступной формы.
3. Пройдите шаги. Используйте вымышленные сведения. Участники, собственность, голоса, решения и подписи не подставляются из демопрофилей.
4. Незавершенный проект можно сохранить кнопкой **«Сохранить черновик»**. Продолжение — вкладка **«Мои проекты» → «Открыть проект»**. Автосохранение запускается через 800 мс после изменения. «Сохранено» появляется только после успешной записи. При ошибке или конфликте ввод остается в редакторе.
5. На шаге **«Проверка и предпросмотр»** исправьте пропуски. **«Подготовить для проверки»** — статус проекта, а не утверждение сметы или признание собрания законным.
6. На шаге **«Сохранение и выгрузка»** доступны настоящие DOCX, печать / сохранение в PDF, для сметы также XLSX. Word-файл содержит редактируемые абзацы и таблицы, а не текст с переименованным расширением. При первой выгрузке приложению нужен доступ к его ресурсам для загрузки компонентов экспорта.
7. Полная форма остается у председателя. Если нужна публикация, отдельно откройте **«Подготовить копию для жителей»**, отредактируйте текст и проверьте персональные сведения в свободных формулировках, поставьте подтверждение и нажмите **«Опубликовать информационную копию»**. Жители получат сокращенную информацию, а не полный протокол или реестр.

### Расчеты, решения и выгрузка

Смета разделяет управление без содержания, содержание общего имущества, отдельный план накоплений и отдельный план целевых сборов. Денежная арифметика выполняется кодом на целых тиынах с округлением половиной вверх. Количество допускает четыре знака после запятой, цена — два. Число выполнений в год вводится явно. Проверяются сумма площадей, повторяющиеся помещения, значения и обоснования.

Только для ограниченной области квартир/нежилых помещений применяются п.10–11 методики: `Р=управление+содержание`, `В=(Р−Д)/(S×12)`. Взнос помещения рассчитывается из исходной дроби и его полезной площади, без промежуточного округления ставки. Паркинг/кладовки и обязательные накопительные/целевые взносы не рассчитываются этой формулой. При доходе выше расходов отрицательный взнос не выводится. Структура 30/70 по п.21 проверяется как предупреждение для ОСИ; специальные случаи не объявляются проверенными автоматически.

Местный минимум Павлодара **не проверен и не зашит в код**. Можно указать территорию, ссылку, период и показатель как исходные сведения пользователя; это не подтверждает соответствия местным требованиям.

Проверка голосования ограничена заполнением и арифметической суммой по каждому вопросу/каналу. Юридические пороги **не вычисляются**: пункты 11 и 12 Правил и специальный случай лифта имеют разные условия. Показывается **«Недостаточно данных для проверки»**. Число квартир, жителей и строк регистрации не превращается в число голосов. Итоги и формулировки решений вводит человек.

XLSX содержит 6 листов: «Инструкция», «Исходные данные», «Статьи расходов», «Сводная смета», «Помещения», «Основания и ограничения». Желтым выделен ввод, голубым — формулы. Числа записаны числами. Строки, разделы и взносы связаны формулами; расчеты помещений не используют округленную ставку. Применено округление половиной вверх до тиына. При ошибках расчетной базы итоговые ячейки пусты, статус показывает ошибку. Включены `IFERROR`, проверки типов, точности, положительной площади, периодов, дохода и дублирующихся помещений.

Подготовлены пустые строки с формулами. Для дополнительных расходов заполните такую строку; если они закончились, скопируйте целую строку с формулами ниже и замените ввод. Итоги используют колонки целиком. Защиты листов нет. Сохраненные результаты рассчитаны кодом приложения; ExcelJS формулы **не вычисляет**. Запрошен пересчет при открытии. LibreOffice проверен с отдельным профилем принудительного пересчета OOXML; в настройках программы пользователя пересчет импорта может быть отключен, тогда нужно выполнить полный пересчет (Ctrl+Shift+F9 в Calc). Настольный Microsoft Excel не проверялся.

Файл — самостоятельная копия, его изменения не возвращаются в приложение. Пользовательский текст, начинающийся с `=`, остается строкой. Макросов, внешних ссылок и отправки данных нет. Сверхбольшие числа ограничены точностью табличных приложений: экспорт отклоняет произведения исходных величин строки за пределами точного целого JavaScript.

### Статусы, версии и доступ

У проектов мастера отдельные статусы: **«Черновик»**, **«Подготовлен для проверки»**, **«Архив»**. Публикация жителям хранится отдельно и не означает подписание, утверждение сметы или принятие решения. Скачивание также не меняет юридический статус.

Полный проект сохраняет версию шаблона, его нормативные сведения, снимки шаблонов приложений и сформированные блоки. Изменение реестра не меняет ранее сохраненный проект при просмотре. Правки оригинала помечают прежнюю копию «Требует обновления», не меняя ее опубликованный текст. Новая публикация архивирует прежнюю копию. История содержит текст и версию источника каждой публикации. Архивирование оригинала архивирует активную копию. Конкурентное сохранение проверяет номер и уникальный идентификатор редакции; отложенные автосохранения используют Web Locks, если API доступен.

Для жителей председатель готовит отдельный текст с предпросмотром и подтверждением. В исходный вариант входят повестка, решения и введенные числовые результаты, для сметы — названия работ и суммы. Реестр участников, доверенности, контакты и подписи не подставляются. Свободный текст **может содержать ФИО и другие персональные сведения**: автоматическое обезличивание не обещается. Председатель редактирует и проверяет формулировки вручную, не меняя смысл решений. Полный проект не заменяется копией. Внешняя ИИ-модель не подключена.

Аддитивная миграция вводит `wizardDataVersion: 2` при сохранении общего `schemaVersion: 2` и формата документов `formatVersion: 1`. Переносятся номера прежних шагов сметы; пользовательский ввод, снимки шаблонов, сформированные блоки, публикации и остальные записи сохраняются. Перед записью обновления создается точная резервная строка `uykomek-data-v1-backup-before-wizard-v2`. Неизвестная версия не сбрасывается. Старым документам не приписывается выдуманная карточка дома.

### Удобная смета 0.4

Семь шагов: дом и год → исходные данные и площади → управление → содержание → другие сведения → проверка и предпросмотр → сохранение и выгрузка. Периодичность: ежемесячно 12, ежеквартально 4, раз в год 1, свое целое количество 1–366. Показывается формула каждой строки, доступны дублирование и удаление с подтверждением.

В «Карточке дома» хранятся название ОСИ, адрес, составитель, полезные площади и исходные ссылки. Новый документ получает независимый снимок. В старом черновике действие «Сравнить с карточкой дома» показывает старые и новые значения, замена требует подтверждения. Полезная площадь не подменяется площадью здания. Неполный реестр допускается явно: ставка возможна при отдельно известной полной площади, индивидуальные суммы — только для известных площадей; полного реестра начислений нет.

«Создать на другой год» создает новый документ, оставляет исходник неизменным и требует подтвердить проверку старых цен и периодичности. Проверка разделена на «Нужно исправить», «Требует внимания», «Не проверяется автоматически», сообщения ведут к полям. Ошибки блокируют итоговую расчетную выгрузку, но не сохранение черновика. При конфликте предлагается открыть новую версию или сохранить свой ввод отдельной копией.

[Простая инструкция председателю](docs/CHAIR_GUIDE.md). [Результаты проверок](VERIFICATION.md).

Код: `src/wizard/registry.ts` — реестр; `models.ts` — сущности; `calculation.ts` — точная арифметика; `rules.ts` — проверка/процедурные основания; `engine.ts` — заполнение и снимки; `store.ts` — сохранение/доступ/публикация; `exports.ts` — OpenXML; `WizardPage.tsx`, `Fields.tsx`, `FormView.tsx` — интерфейс.

## Как открыть на Windows

1. Установите Node.js **LTS** с nodejs.org (версия 22 или новее), если он ещё не установлен.
2. Распакуйте архив проекта. Откройте папку, в которой находятся `package.json`, `src` и `public`.
3. В строке адреса Проводника введите `cmd` и нажмите Enter.
4. Выполните по очереди:

```sh
npm ci
npm run dev
```

5. Откройте адрес из строки `Local` в появившемся окне. Обычно это `http://localhost:5173`. Командное окно оставляйте открытым.

Адрес localhost работает на том компьютере, на котором запущена команда. Он не является ссылкой на опубликованный сайт. Сам файл index.html двойным щелчком открывать не нужно. Для сборки: `npm run build`; для проверки готовой сборки: `npx vite preview --host 0.0.0.0 --port 4173`.

В облачной машине npm можно запускать с `--cache /tmp/uykomek-npm-cache`, если домашняя папка недоступна для записи.

## Что изменилось

- Документы имеют статус «Черновик», «Опубликован» или «Архив», аудиторию, даты и номер версии. Новые документы и отчеты всегда черновики. Публикация и архивирование требуют отдельного подтверждения. При редактировании опубликованный документ возвращается в черновики.
- Житель видит только опубликованные документы своего дома с аудиторией «Жители и председатель». Его помощник использует те же ограничения. Архив исключён из актуального поиска обоих профилей. Если источник старого ответа стал недоступен, текст ответа скрывается.
- Главные рабочие экраны стали компактнее. У председателя есть счетчики обращений и черновиков, быстрые действия и финансовые итоги. У жителя — важное объявление, последнее собственное обращение, поле вопроса, опубликованные документы и расходы.
- Обращения содержат дату, место, срок, исполнителя и результат. Переписка отделена от истории статусов и назначений. Без результата закрытие запрещено. Житель может описать нерешенную проблему и вернуть собственное выполненное обращение в работу.
- Просрочка — только срок раньше сегодняшнего дня по времени Казахстана и статус, отличный от «Выполнено». Сегодняшний срок или отсутствие срока не считаются просрочкой.
- Выбор месяца влияет на расходы, новые отчеты и новые ответы помощника. Работу можно редактировать; событие содержит старые и новые суммы и дату. Факт может превышать план; разница тогда отрицательная. Это **не остаток банковского счета** — поступления и банковская интеграция отсутствуют.
- Новый отчет содержит неизменяемый снимок работ и сумм с датой подготовки. Изменение расходов не меняет уже сохранённый отчет. При редактировании текста отчета таблица исходного снимка сохраняется; отличающийся текст автора отдельно показывается и печатается.
- Для отчетов есть печать и сохранение в PDF средствами браузера. В печать выводятся название ОСИ, адрес, месяц, суммы, таблица, результаты и дата; меню, чат и кнопки скрываются. Старые текстовые отчеты сохраняются текстовыми документами: исторические суммы из них не реконструируются.

## Проверить за 10 минут

1. Войдите как житель, создайте обращение с местом проблемы. Откройте вторую вкладку того же адреса и войдите как председатель.
2. Назначьте обращению срок и исполнителя, отправьте сообщение через отдельную переписку. Чтобы проверить просрочку, выберите вчерашний срок.
3. Попробуйте закрыть обращение без результата — сохранение будет отклонено. Укажите результат и закройте. У жителя напишите, что осталось нерешённым, и верните обращение в работу.
4. У председателя добавьте документ. Нажмите **«Сохранить черновик»**. Житель не должен его видеть, в том числе через помощника.
5. Нажмите **«Опубликовать»**, проверьте аудиторию и подтвердите. Теперь документ доступен жителю. Отправьте его в архив — из актуального списка и поиска он исчезнет.
6. Проверьте аудиторию «Только председатель»: даже опубликованный документ с этой аудиторией жителю недоступен.
7. Выберите месяц, добавьте работу с планом и фактическим расходом. Подготовьте отчет и сохраните черновик. Затем измените расход. Новый вопрос помощнику использует новую сумму, а сохранённый отчет — прежнюю.
8. Откройте сохранённый отчет через «Просмотреть» → **«Печать / Сохранить в PDF»**. В окне печати выберите «Сохранить как PDF».
9. В верхней части кабинета откройте **«Режим демонстрации»**. Сравните профили и доступные дома. Это явно обозначенный инструмент демонстрации, а не настоящая авторизация.

Если вы уже пользовались первой версией, остановите старый сервер сочетанием Ctrl+C в его командном окне, затем запустите новую папку проекта командой npm run dev. Перед обновлением закройте старые вкладки приложения и откройте новую версию по тому же адресу. Данные разных адресов/портов браузер хранит отдельно. Не очищайте данные сайта, если хотите сохранить записи.

Вместо условного owner='resident' используются userId, houseId, помещения и принадлежность пользователя к дому с ролью. Переключатель дома показывает только дома выбранного профиля. ## Данные, миграция и восстановление

- Единый источник данных — localStorage. Ключ `uykomek-data-v1` сохранён для совместимости; внутри новый формат обозначен `schemaVersion: 2`.
- Старый формат мигрирует автоматически. Перед записью v2 сохраняется точная копия исходной строки в `uykomek-data-v1-backup-before-v2`. Она не перезаписывается при повторном открытии. Если места на копию/новую запись нет, миграция останавливается с объяснением, исходные данные не сбрасываются.
- Сохраняются идентификаторы, пользовательские тексты, фото, суммы, даты работ и события. Старые `owner='resident'` и `owner='other'` получают постоянные профили. Неизвестный старый владелец получает отдельный демопрофиль. Старые ответы, записанные через « · » в истории, переносятся в переписку; статусы — в отдельную историю.
- Пять исходных демонстрационных документов сохраняются опубликованными. Пользовательские документы и проекты отчетов старого формата мигрируют в черновики. Их тексты не теряются, но для жителей потребуется отдельная публикация. Если старой даты документа не было, датой создания/обновления становится время миграции; историческая дата не выдумывается. Для проверки разделения добавляются вымышленные записи второго дома «Самал»; старые записи первого дома сохраняются. Старая версия не сохраняла отдельный результат закрытия — он не реконструируется из свободного текста.
- Неизвестная версия или поврежденный JSON не сбрасываются молча. Появляется экран с сохранением исходной копии, повторным открытием и **отдельно подтверждаемым** восстановлением демоданных.
- При переполнении или запрете записи приложение показывает ошибку; неуспешная операция не считается сохранённой. Фото: JPG/PNG/WebP до 1,5 МБ, проверка типа, размера, декодирования, предпросмотр. localStorage имеет небольшой лимит, зависящий от браузера.
- В «Режиме демонстрации» можно скачать текущие данные JSON и сбросить их после подтверждения. Импорт копии через интерфейс в этой версии не реализован; исходная резервная копия остаётся в браузере.
- Изменения обновляют другие вкладки того же origin (схема, адрес и порт). **Разные телефоны, компьютеры, браузеры, профили и адреса не синхронизируются.** Для этого нужны сервер и общая база. При одновременных записях разных вкладок возможен принцип «последняя запись побеждает»; документы и расходы дополнительно проверяют версию/дату при редактировании. Полной транзакционной защиты в браузере нет.

## Помощник

Локальная реализация без внешних вызовов. Он учитывает профиль, дом, месяц, доступные документы, собственные обращения и актуальные расходы. Для нескольких собственных обращений предлагает выбор. Указывает использованные записи, даты и переходы. Примеры:

- «Какие обращения просрочены?»
- «Какие документы доступны жителям?»
- «Сравни план и фактические расходы»
- «Подготовь отчет за выбранный месяц» (председатель)
- «Найди документ: смета» — **поиск по тексту**, а не понимание содержания
- «Что сделано по моему обращению?»
- «Подготовь объявление из этих данных» (председатель)

Для объявления открывается форма: событие, дата, время, причина, контакт. Затем пользователь проверяет текст и отдельно подтверждает публикацию. Подготовленный ответ по обращению переносится в редактор сообщения и отправляется только пользователем. Документы и отчеты сохраняются черновиками; публикация — отдельное действие. Помощник не меняет расходы и не закрывает обращения. Сообщение об ошибке записывается только в локальную историю событий, никуда не отправляется. Юридическая база не подключена; нормы законодательства не генерируются. Неизвестные вопросы получают честное сообщение об ограничении.

`AIAdapter` допускает синхронный демо-ответ или Promise для будущего провайдера. При интеграции внешней модели понадобятся серверный адаптер, обработка ожидания/ошибок в UI и серверная проверка доступа. **Ключи должны храниться только на сервере**, никогда в клиентском коде, localStorage или переменных VITE_*.

## Структура проекта

- `src/main.tsx` — запуск и экран восстановления при ошибке хранилища.
- `src/App.tsx`, `src/AppContext.tsx` — общая оболочка, выбранный контекст и операции сохранения.
- `src/pages/` — отдельные рабочие страницы; публичная страница сохраняет прежний дизайн.
- `src/components/` — общие элементы, формы, диалоги подтверждения.
- `src/models/` — типы сущностей и контекста.
- `src/store/` — адаптер localStorage, миграции, выборки по правам и операции изменения. Интерфейс `ServerRepository` обозначает асинхронную границу будущего серверного API; сервера сейчас нет.
- `src/assistant/` — сценарии помощника и интерфейс AIAdapter.
- `src/reports/` — расчеты, снимки, текстовый и печатный отчет.
- `src/data.ts` — небольшая совместимая точка экспорта модулей, без отдельного хранилища.

Основной язык — русский; неработающего переключателя языка нет. Для казахского перевода нужно вынести строки интерфейса в общий словарь.

## PWA и офлайн

Manifest, обычные и maskable-иконки, service worker сохранены. Установка требует HTTPS или localhost и поддерживающего браузера. Android: Chrome → меню → «Установить приложение». iPhone: Safari → «Поделиться» → «На экран Домой». В «Режиме демонстрации» есть справка установки. После первой загрузки **готовой сборки** ресурсы кешируются для повторного открытия без сети; режим разработки не является целевым офлайн-сценарием. Кеш приложения обновлён для новой версии. Установка на физических телефонах в облачной машине не проверяется.
